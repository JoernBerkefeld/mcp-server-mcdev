The following metadata types are currently supported:

**v10:** Content Builder emails use selector `asset-email`, directory `asset/email/` and suffix `.asset-email-meta.*` instead of the old `message` grouping. Members remain `templatebasedemail`, `htmlemail`, `textonlyemail` and API `message` (ID 5); API names/IDs are unchanged. `jsonmessage` belongs to `asset-mobile`; `jsonmessagetemplate` remains in `asset-template`. Historical web/page/code-resource layouts migrate to `asset-webstudio` according to their owning type. See [Migrating to v10](/Accenture/sfmc-devtools/wiki/03.a-~-Migrating-to-v10#asset-layout-migration) for the complete mappings.

**Asset creation exception:** All `asset-webstudio` members must be created in the SFMC UI first. mcdev can update their existing content or key, but cannot create them, including web templates, microsites, interactive content, and code resources—not just CloudPages.

Current asset groups are `archive`, `asset`, `audio`, `block`, `code`, `document`, `image`, `email`, `mobile`, `other`, `package`, `rawimage`, `template`, `textfile`, `video`, and `webstudio` (use `asset-<group>` to select one). Default retrieval selects `asset`, `block`, `code`, `email`, `mobile`, `other`, `template`, `textfile`, and `webstudio`. `asset-package` is optional and not retrieved by default; it recognizes `packagedefinition` and `packagedeployment`. Other recognized members include `gpg` and `archive` in `archive`, `iccloudpageblock`, `einsteincontentselectionblock`, and `einsteincontenttesting` in `block`, `contentmap` in `other`, and `jbtemplate` in `template`. Recognition/grouping is not a guarantee that every member supports every CRUD operation.
