If you installed mcdev globally as described above you can run mcdev in any directory. See our [install Accenture SFMC DevTools](/Accenture/sfmc-devtools/wiki/02.-Getting-Started#install-accenture-sfmc-devtools) chapter for more details.

_Example (global install):_

```bash
mcdev retrieve
```

If you installed Accenture SFMC DevTools as a local dependency (**not recommended**) to the current directory then you will have to add `npx` in front of each command. See our [Local install](/Accenture/sfmc-devtools/wiki/10.-Contribute#local-install) chapter for more details.

_Example (local install):_

```bash
npx mcdev retrieve
```

The following description will assume a global installation for simplicity reasons.

_Note:_ Parameters listed below in between square brackets = `[...]` are optional parameters. Required parameters are listed in between less-than / greater-than signs = `<...>`.

_Note:_ Most commands allow interactive credential/Business Unit selection: use `?` if more parameters follow, or omit them if no other required parameters follow. `mcdev migrate` follows the same rule — omit its `cred/bu` argument to select interactively (the argument also accepts `cred/*` to run every BU of one credential), and `--skipInteraction` (or `--yes`) errors instead if selection is required. For `migrate`, only exact `cred/*` for a configured credential expands to all its BUs. Other unresolved selectors, including bare `*` and `unknownCredential/*`, use the existing interactive credential/BU selection; noninteractive mode logs an error instead. Selectors with extra slash components or empty components are rejected without selection. There is no separate branch-confirmation prompt. See [migrate](/Accenture/sfmc-devtools/wiki/06.a-~-Admin-Commands#migrate).
