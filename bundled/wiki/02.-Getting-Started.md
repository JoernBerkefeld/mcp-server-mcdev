Accenture SFMC DevTools can be installed as Node.JS package.
The following guide will demonstrate how you can get started within 10 minutes or less.

## Pre-requisites

### Install Node.js with npm

Starting with v10, the CLI and generated project tooling require Node.js `^22.22.2 || >=24.15.0`. Prefer a supported LTS (Long Term Support) release. Node 20, 21, all Node 23 versions, earlier Node 22 patches and Node 24 before 24.15.0 are unsupported by v10. These requirements apply starting with v10; v9 requirements are unchanged.

1. To check if it is already installed, at the OS command prompt, type: `node --version`
    - For v10, a compatible version is Node 22.22.2 or later within Node 22, or Node 24.15.0 and later. If your version is incompatible, continue to step 2; otherwise proceed to the next installation.
    - If you get a "command not found" error message, continue to step 2.
2. In a web browser, go to [nodejs.org](https://nodejs.org)
3. Download and run the latest **LTS** installer for your operating system.
4. When the installer finishes, try step 1 again. If it fails, please restart your terminal. If it still does not work, reboot your computer and try the version check then.

The editor's ESLint extension may use a different Node runtime from your terminal. For v10, check both; if the editor runtime is too old, set `eslint.runtime` to the absolute path of a supported Node executable and restart the ESLint server. Update CI runners and containers too. The v10 CLI rejects unsupported runtimes before loading its main dependencies.

### Install the Git Command Line

> **Pending release:** optional-Git setup is implemented locally on the bundled-fallback feature branch, not yet publicly released. Ordinary retrieve/deploy operations do not require Git. With the pending changes, `init` and `upgrade` warn when Git is unavailable, continue non-Git setup, and skip all Git initialization, remotes, staging, commits and pushes. Failures from installed Git remain errors. `mcdev join` and Git-backed delta packages require Git and return a nonzero CLI exit when Git is unavailable.

1. To check if git is already installed, at the OS command prompt, type: `git version`
    - If this command reports a git version such as "git version 2.31.0" (or "git version 2.31.0.windows.1" on Windows), you're done. Proceed to native Android or iOS environment setup.
    - If you get a "command not found" error message, continue to step 2.
2. Go to [git-scm.com/downloads](https://git-scm.com/downloads).
3. Under Downloads, click the icon for your operating system.
4. Run the installer.
5. When the installer finishes, try step 1 again. If it fails, please restart your terminal. If it still does not work, reboot your computer and try the version check then.

## Install Accenture SFMC DevTools

If you experience issues installing Accenture SFMC DevTools, please check out the [Troubleshooting](/Accenture/sfmc-devtools/wiki/04.-Troubleshooting) section in this manual.

**How to:**

1. Install Accenture SFMC DevTools by running `npm install -g mcdev` (prefix with `sudo` on MacOS)
    - If you get an error, please see the [troubleshooting](/Accenture/sfmc-devtools/wiki/04.-Troubleshooting) section.

When completed run `mcdev --version` and it will show you which version you installed (e.g. `9.0.3`).

> **_Side note for proud nerds_:**
>
> The `-g` part behind `npm install` triggers a so-called "global installation". This is a term coined by Package Managers, in this case Node's package manager (npm) and it means that Accenture SFMC DevTools is installed on your computer and usable across projects. The alternative is a "local installation" would install Accenture SFMC DevTools only for the current project folder. This local install is a technique used to ensure everyone in the team is using the same version of a tool. Nevertheless, we strongly recommend going with the global installation to be able to use the full feature-set of Accenture SFMC DevTools.
>
> You may choose to install mcdev globally or locally. Global install runs faster and allows you to initialize new projects by running `mcdev init` in any directory. If your project does require a local installation, please refer to the [Local Install Guide](/Accenture/sfmc-devtools/wiki/9.-Contribute#local-install).

### Extension-bundled CLI (pending release)

The local, unreleased bundled-fallback extension includes mcdev: extension commands require no separate global or project-local mcdev install. `sfmc-devtools-vscode.mcdevSource` defaults to `auto`, selecting project-local mcdev, then mcdev on PATH, then the bundle. Explicit `bundled` uses only the extension copy; `custom` uses `sfmc-devtools-vscode.mcdevPath`. Explicit choices never silently fall back; failed operations are not retried with another version.

Node and npm must remain on PATH for the IDE and terminals; restart VS Code/Cursor after installation or PATH changes. See the [extension README](https://github.com/Accenture/sfmc-devtools-vscode/blob/main/README.md) for supported runtimes and portable Windows user-PATH instructions. Bundled updates arrive with extension updates, not global npm updates. The bundle does not expose a standalone `mcdev` terminal command. Fresh-folder command visibility is unchanged: if Initialize Project is unavailable, use a separately installed CLI for `mcdev init`.

## Initial project setup

After the successful installation, you will now need to set up the connection to your Marketing Cloud instance.

1. In your Marketing Cloud instance
    1. Ensure that you **selected** your **Parent/Global Business Unit**.
    2. Go to `Setup -> Apps -> Installed Packages`.
    3. Create a new "installed package" and name it "Accenture SFMC DevTools Deployment Tool"
        > Note: On some older SFMC instances it will ask you if you want the enhanced version. Please enable this option.
    4. Click on the _Add Component_ button and select `API Integration` with `Server-To-Server` mode.
    5. Make sure you grant all available rights.
    6. Go to the access tab and grant it access to all Business Units that you want to use it for, but ensure that the Parent/Global Business Unit is among these.
        - _Why?_ Shared Data Extensions, roles, users, Business Unit info and some other metadata is internally stored solely on the parent Business Unit and hence can only be retrieved and updated via that BU.
    7. Note down _EID_ (Parent MID), _Client Id_, _Client Secret_ and _Authentication Base URI_.
2. In your project folder
    1. Open a CLI in your project folder (e.g. `C:\repos\MyProject\` on Windows or `~/repos/MyProject/` on Mac)
    2. Run `mcdev init` to start the interactive setup wizard.
        1. If not found yet, default configuration files will be copied into your project folder and an npm project initialized. The pending optional-Git behavior above skips Git repository setup when Git is unavailable.
        2. The wizard will ask you to name your credential. The name you choose here will be used by all team members because the config is shared via Git.
            > Being specific here reduces the chance of deploying to the wrong server (instance) in stressful situations. We suggest you use something like `ClientName`, or `ClientName-ProjectName` if you have multiple projects with the same client. In case your project uses multiples instances you might like to use something like `Client-ProjectName-Sandbox` and `Client-ProjectName-PROD`.
        3. It will then continue to ask for the EID (Parent MID), client ID, client secret and Authentication Base URI.
        4. The credentials will be automatically tested & your list of BUs downloaded until finally the central configuration file `.mcdevrc.json` gets created in your project folder.
        5. The wizard offers an initial backup and Git commit. With the pending optional-Git behavior, non-Git setup continues without Git, but Git staging, commit and push are skipped.
    3. If this is the first time you set up Accenture SFMC DevTools or you recently upgraded Accenture SFMC DevTools, please restart VS Code now! A pop-up will likely appear in the lower right corner prompting you to install recommended extensions.
    4. Done.
3. Sharing the project with your team (requires Git; skip this section when working without Git)
    1. Make sure you have a Git repo (Bitbucket, GitHub, GitLab) set up somewhere. If you are an SI partner, usually, your client will have to do this for you.
        > If `mcdev init` created a local Git repository, upload ("push") it to the online repository. If setup skipped Git, install Git and initialize the repository before following these sharing steps:
    2. Open the URL of your online repo and find the "CLONE" button. This will likely show you a normal URL, ending on ".git"
    3. Add this as your repository remote named "origin". If you use a GUI-based tool, that should be fairly simple, otherwise, execute `git remote add origin YOUR-URL` in your project folder.
    4. Now run `git push -u origin master` to start the upload.

## Joining a project that was set up before

If Accenture SFMC DevTools was already used to set up the project by somebody in your team, including all of the steps in the above chapter [Initial project configuration](#initial-project-setup), then basically you are in luck. Things are much faster from here on:

1. Make sure you went through the chapters [Pre-requisites](#pre-requisites) and [Install Accenture SFMC DevTools](#install-accenture-sfmc-devtools). Do skip [Initial project configuration](#initial-project-setup)!
2. Acquire the URL to your Git repo and Clone it to your computer. It should end on `.git`. Also ask your team lead for `EID (Parent MID)`, `Client ID`, `Client Secret` and the `Authentication Base URI`. You will need this later.
    > We recommend you create a folder like `C:\repos\` and clone the repo for your current project into that. By default, the repo name will be suggested as a sub-folder name which you should keep in place. That way you will always have one folder in which all your projects can be found in with their respective sub-folders.
3. Open your main repo folder (e.g. `C:\repos\`) in the CLI of your choice (e.g. PowerShell on Windows)
4. Assuming you installed Accenture SFMC DevTools globally (recommended!), now execute `mcdev join`.
5. It will ask you for your git repo's URL (ending on .git) and then commence cloning it.
6. The system will then recognize the previously set up project and ask you for `EID (Parent MID)`, `Client ID`, `Client Secret` and the `Authentication Base URI`.
7. Done.

## Recommended additional installs

The following seeks to enhance your daily process. Our guide assumes that you are using [Visual Studio Code](https://code.visualstudio.com/download) to develop, backup and deploy your project. For smooth operations, we highly recommend the following Marketing Cloud specific plugins for it.

Nevertheless, Accenture SFMC DevTools will run without them and is not associated with the development of these publicly available apps & plugins.

> **Note:** The following lists are automatically installed when you run `mcdev init` or `mcdev upgrade`.

**Visual Studio Code extensions:**

When you run `mcdev init` or `mcdev upgrade` we add/update the file `.vscode/extensions.json` in your project directory with a list of recommended VSCode extensions that will help your daily workflow with Salesforce Marketing Cloud.

Restart VS Code after cloning a prepared repo or after you've run `init` / `upgrade` and VS Code will prompt you in the lower right corner with:

![Recommended extension prompt](img/README.md/vscode-recommendations-1.png)

Click on `Install All` to quickly get things ready or review the recommendations first via `Show Recommendations`. If you opt for the second option, be aware that there are 2 kinds of recommendations:

![Recommended extension prompt](img/README.md/vscode-recommendations-2.png)

The "Workspace Recommendations" were defined by Accenture SFMC DevTools. Clicking on the little cloud icon will install all at once. The "Other Recommendations" are auto-generated by VS Code and are not controlled by Accenture SFMC DevTools. You _may_ look through those as well, but they might also be completely irrelevant to you.

**Node modules starting with v10:**

-   [eslint](https://npmjs.com/package/eslint) and `@eslint/js`: linting with `eslint.config.js`; core recommended checks are scoped to browser/Node JavaScript.
-   [eslint-plugin-sfmc](https://npmjs.com/package/eslint-plugin-sfmc): canonical standalone and embedded SFMC language parsing, globals and diagnostics.
-   [eslint-plugin-unicorn](https://npmjs.com/package/eslint-plugin-unicorn): scoped to JavaScript/SSJS with canonical SFMC compatibility overrides for SSJS. Tooling defaults come from the installed mcdev package's manifest. For managed tooling, only equal/newer simple versions in `devDependencies` (optionally prefixed with `^` or `~`) are preserved; missing, older or non-simple specifications are installed at the default version. A declaration in `dependencies` alone does not satisfy this check.
-   [eslint-plugin-jsdoc](https://npmjs.com/package/eslint-plugin-jsdoc): recommended checks for browser JavaScript and Node hooks/helpers, not SSJS; Node hooks use TypeScript-flavored type parsing, not the typed-JavaScript preset.
-   [globals](https://npmjs.com/package/globals): browser and Node builtin globals in their respective scopes.
-   [eslint-config-prettier](https://npmjs.com/package/eslint-config-prettier): last in the ESLint config to disable conflicting style rules; it does not run formatting.
-   [prettier](https://prettier.io) and [prettier-plugin-sfmc](https://npmjs.com/package/prettier-plugin-sfmc): separate formatting for AMPscript, mixed SFMC HTML, Handlebars, SSJS and T-SQL.

Generated projects retire `eslint-config-ssjs`, `eslint-plugin-prettier` and the `eslint-check` script; pre-v10 migration also removes `prettier-plugin-sql`. This does not change mcdev's own contributor lint stack. The generated scripts are:

- `npm run lint`: `eslint .` for diagnostics without automatic fixes.
- `npm run lint:fix`: `eslint . --fix` for lint fixes.
- `npm run format`: `prettier . --write` for separate formatting.
- `npm run format:check`: `prettier . --check` for formatting checks without writing.

Run both `lint` and `format:check` in CI; a combined `check` script is not generated.

See the [v10 migration guide](/Accenture/sfmc-devtools/wiki/03.a-~-Migrating-to-v10) for exact commands and upgrade safeguards. Browser ESM linting applies only to real `.js` files under `retrieve/` and `deploy/`; standalone and HTML-extracted SSJS use canonical SFMC handling instead. Node ESM hooks are `.mcdev-validations.js` and `lib/**/*.js`; `eslint.config.js` is Node tooling. HTML-extracted server blocks are excluded from browser/Node overrides, and inline client-side HTML scripts are not linted by the SFMC processor.

In the v10 editor settings, HTML remains `html`, standalone AMPscript uses lowercase `ampscript`, and `.ssjs` uses `ssjs`. Prettier owns formatting for HTML, AMPscript, SSJS and JavaScript; ESLint validation and fix actions run separately. Configuration files are updated one at a time: missing files are created, identical files are reported as unchanged, and ordinary differing files have an optional Yes-default override prompt. Declining skips only that file; historical version-gated replacements and `--skipInteraction` bypass the prompt. Replacements preserve the old file as `.BAK`; an older backup is replaced with the latest pre-upgrade file, so repeated upgrades continue and refresh it. Start from a clean committed state and review existing settings, because there is no automatic rollback and project-specific associations must be reapplied as needed.

Please note that Visual Studio Code might warn you about using the local installation of ESLint with a pop-up like the following. Please confirm this with `Allow` or, if you are certain about what you are doing, with `Allow Everywhere`. Inside of Accenture SFMC DevTools project folders this warning is normal because we ask to install the VSCode extension and the node module for ESLint.

## Using mcdev in other node packages

Install it locally first via the following (or with a [specific version](/Accenture/sfmc-devtools/wiki/4.-Troubleshooting#installing-a-specific-version)):

```bash
npm install --save mcdev
```

And then import it in your code using ES modules:

```javascript
import mcdev from 'mcdev';

// download all metadata from your instance's Parent BU
mcdev.retrieve("MyCredential/_ParentBU_");

// or download only dataExtensions from your instance's Parent BU
mcdev.retrieve("MyCredential/_ParentBU_", "dataExtension");
```

> :warning: **Note:** CommonJS `require()` syntax is no longer supported since version 6.0.0. Use ES module imports instead.

For more details on the available methods look out for what Intellisense will return or refer to the [developer documentation](/Accenture/sfmc-devtools/blob/main/docs/dist/documentation.md).
